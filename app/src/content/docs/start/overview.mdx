Clava organizes its documentation around a simple path: understand the mental model in Start, deepen it in Guides, and use Reference when you need precise signatures or release history.

## Reading path

- Read [Installation](/start/installation/) if you are adding Clava to an existing project.
- Read [Quick Start](/start/quick-start/) if you want the smallest useful `cv()` example.
- Read [First Component](/start/first-component/) if you want to see the same component rendered in multiple output modes.

## Site structure

- `Start` covers onboarding and the shortest path to a working component.
- `Guides` splits into core concepts and recipes so the mental model and the applied patterns do not compete with each other.
- `Reference` keeps the public contract, generated symbol pages, and changelog in one place.

:::note
This v0 site already uses its long-term structure. Some pages are still placeholders, but the navigation is intended to remain stable as the content grows.
:::
